# Notes for agents

nativeps5-kyty is the Kyty component of nativeps5 (a fork of KytyPS5): an alternative GPU back end for translated
titles. On macOS arm64 it is built as the shared library `kyty_gpu.dylib` (target `kyty_gpu`) that the ps5recomp
runtime loads when `NPS5_GPU=kyty`; the game's event queues, pad and process exit stay in nativeps5-anyps5. It
recompiles AMD shaders to SPIR-V and runs them on Mesa KosmicKrisp (Vulkan on Metal). It is not an emulator of the
guest CPU.

The project-wide rules are in https://github.com/computerguy526/nativeps5 [AGENTS.md](https://github.com/computerguy526/nativeps5/blob/main/AGENTS.md). Read it first. In short: the game-data rule (never game data or anything derived from a title in a commit, issue, PR or prompt; derived files live under `NPS5_SCRATCH`); the run safety rules (one GPU-using process on the machine, title runs only through `scripts/run-title.sh` of the entry repository, never raise `NPS5_SELF_MEM_LIMIT_MB`, no Metal counter heaps or GPU timestamp queries, no screenshots, kill only what you started); evidence for every speed or picture claim (`nps5 report`, A/B with interleaved runs, scene named, commits of every component); and git: the identity comes from git's configuration (never `--author`, `-c user.*` or `--no-verify`), no pushes to an upstream, and the pull request template states whether AI assisted.

## Upstream rules (still apply)

KytyPS5 has no agent rules of its own; its code style is what the tree shows (tabs, the existing naming and
`EXIT_IF` conventions). Match the surrounding file, keep third-party code under `3rdparty/` with its licence
(`LICENSES`, `NOTICE`), and do not bring in GPL-3.0 code. Where nativeps5 differs: the host is macOS arm64 and the
Windows launcher is not built (`-DKYTY_BUILD_LAUNCHER=OFF`).

## Where things live

| Path | What |
|---|---|
| `src/hybrid/` | the hosted-renderer bridge: `kytyGpuBridge.cpp` (the exported C API, `kytyGpuApi.h`, `kyty_gpu.def`), `mainLoopGate.h`, `pendingMemory.h`; `kytyGpuNids.inc` is generated |
| `src/graphics/guest_gpu`, `host_gpu`, `presentation` | command processor, the Vulkan renderer and caches, window and present |
| `src/graphics/shader/recompiler` | the shader recompiler; `CodegenFingerprint.cpp` reports `KYTY_CODEGEN_VERSION` |
| `src/graphics/loadCard.h`, `compileProgress.h`, `progressOverlay.h` | header-only load card and progress overlay, testable without a GPU |
| `src/kernel`, `src/libs` | memory, `hostedGuard.h`, and the guest-facing library functions (`libs/agc.cpp`) |
| `tests/` | CPU-only unit tests (one `*Tests.cpp` each, `.inc` files are shader test tables), `tests/hybrid` bridge load test |
| `tools/` | pipeline-list, shader-journal, hangtrace and hybrid build helpers |
| `docs/` | upstream notes plus `EXPERIMENTAL.md`, `HANG-WATCHDOG.md`, `PIPELINE-STUTTER.md` |

## Build and test

```sh
cmake -S . -B build-arm64 -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64 -DKYTY_BUILD_LAUNCHER=OFF \
      -DKYTY_GPU_SDL3_DYLIB=<brew prefix>/lib/libSDL3.0.dylib          # scripts/build.sh kyty does this and the submodules
cmake --build build-arm64 -j 4 --target kyty_gpu                        # nice 5; at most 4 jobs
cmake --build build-arm64 -j 4 --target load_card_tests hosted_guard_tests cp_sequencer_tests && ./build-arm64/load_card_tests
```

Test executables are `EXCLUDE_FROM_ALL` targets named in `CMakeLists.txt` (`<name>_tests`, no ctest); build the
one you need and run it. `.nps5-check-tests` is the list the checker builds and runs (load card, hosted guard and
ranges, hybrid seam, CP sequencer, VRAM budget, GPU safety and others). A guard gets a test that fires it and one that
stays silent on the normal path.

## Rules specific to this repository

- The code defaults are the slow, upstream-compatible path; nativeps5 behaviour is switched on by the title preset
  (`titles/kyty-preset.env` in the entry repository). New behaviour is off by default behind a `KYTY_*` switch unless
  proven neutral or better; the entry repository's `docs/env_switches.tsv` lists them (`scripts/gen_env_switches.py`).
  Test-only switches (for example `KYTY_TEST_CLOSE_S`) say so in their comment and are off by default.
- **Codegen fingerprint.** `KYTY_CODEGEN_VERSION` (generated by `src/codegen_version.cmake`) hashes the recompiler
  source set, the compiler and its flags; the persistent program cache ignores files written by another version, and
  the build fails when a codegen file includes a project header outside the set. A change to codegen therefore
  invalidates every cache: say so in the PR, and expect a re-prepare before measuring.
- **Hosted renderer.** Entry points that the translated program calls go through `kytyGpuBridge.cpp` as plain C;
  no C++ exception crosses it. Do not change the exported names or ABI without `kyty_gpu.def`, `kytyGpuApi.h` and the
  matching AnyPS5 side (`core/libs/nps5/KytyHost.cpp`, `Nps5KytyHostAbi`) moving together.
- `hostedGuard.h` (reader-writer slots guarding hosted memory) and `loadCard.h` have unit tests; keep them passing
  and add to them when you change the logic.
- Generated, do not edit: `src/hybrid/kytyGpuNids.inc` (`tools/hybrid/gen_kyty_gpu_exports.py`) and
  `kytyCodegenVersion.h` / `kytyGitVersion.h` in the build tree.
- No GPU timestamp queries or counter heaps (`KYTY_EOP_TIMESTAMPS=gpu` is forbidden on a title); GPU loops keep their
  caps and the hang watchdog (`docs/HANG-WATCHDOG.md`) stays on.
- Shaders, pipeline lists and journals derived from a title stay under `NPS5_SCRATCH`; the only committed exception is
  a game profile's `pipelines.kyplst` in the entry repository, with its verification record.

Pull requests use `.github/pull_request_template.md` (it points at the entry repository's CONTRIBUTING.md; fill the evidence block with `nps5 report`, see docs/agents/evidence.md there). `scripts/check.sh --tree` of the entry repository run against this checkout must report 0 failures; this repository's `.nps5-check-tests` lists the CPU-only tests it runs.
